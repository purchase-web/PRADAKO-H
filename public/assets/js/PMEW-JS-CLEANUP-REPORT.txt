1. PERMANENT SITE-SHELL LOADER
------------------------------
Permanent owner: pradako-site-shell.js

Why this file was selected:
- It uses the real shared HTML components instead of generating a second navbar/footer in JavaScript.
- It now checks HTTP status before injecting HTML.
- It centralises the shared component paths.
- It dispatches one `pmew:shell-loaded` event after the shell has finished loading.
- It exposes a shared site-root helper through `window.PMEW_SITE`.

Canonical components:
- components/navbar.html
- components/footer.html

The old pmew-site-shell.js is now only a compatibility alias. It no longer creates or fetches navbar/footer markup.

2. NAVBAR/FOOTER OWNERSHIP REMOVED FROM COMPETING FILES
-------------------------------------------------------
Removed direct shared-component fetching from:
- scripts.js
- main.js
- astm-specifications.js
- pmew-site-shell.js

Only pradako-site-shell.js now contains the canonical components/navbar.html and components/footer.html paths.

Backward compatibility:
- scripts.js can bootstrap pradako-site-shell.js if an old page has shell containers but forgot to include the permanent shell script.
- main.js can also bootstrap the permanent shell for legacy pages and only applies its old navbar interactions when scripts.js is not present.
- pmew-site-shell.js delegates to pradako-site-shell.js from the same JavaScript folder.

3. WEB-ROOT / PATH STRATEGY
---------------------------
pradako-site-shell.js derives the website root from its own resolved script URL.

This supports BOTH environments without changing component URLs:

A. Current Live Server setup
   Browser page:
     /public/pages/about-us/philosophy.html
   Shell script:
     /public/assets/js/pradako-site-shell.js
   Automatically resolves:
     /public/components/navbar.html
     /public/components/footer.html

B. Production / public-as-web-root setup
   Browser page:
     /pages/about-us/philosophy.html
   Shell script:
     /assets/js/pradako-site-shell.js
   Automatically resolves:
     /components/navbar.html
     /components/footer.html

No page-depth-specific ../../components/... calculations are required for the shared shell.

Optional override:
  window.PMEW_SITE_ROOT = "/your-root";

Shared helper now available:
  window.PMEW_SITE.root
  window.PMEW_SITE.path("assets/...")
  window.PMEW_SITE.components.navbar
  window.PMEW_SITE.components.footer

4. scripts.js DUPLICATE CLEANUP
-------------------------------
Removed the direct loadComponents() navbar/footer fetcher.
Removed the duplicate global-presence implementation from scripts.js.
Removed the two duplicated APPLICATION NAVBAR ACTIVE + SECTION HASH SCROLL IIFEs.

Application logic is now owned by one:

- initApplicationScrollSpy()

The scrollspy is requestAnimationFrame-throttled to avoid performing the full section scan repeatedly within the same browser frame.

6. COOKIE CONSENT CONSOLIDATION
-------------------------------
Canonical consent core:
- cookie-consent-init.js

UI only:
- cookies.js

The previous conflict was removed: one file used a browser cookie while the other used localStorage under the same name.

New behaviour:
- canonical persistence is the pmew_cookie_consent browser cookie
- 180-day consent duration
- cookie-consent-init.js owns reading, writing, normalisation, expiry, Consent Mode and state
- cookies.js only owns banner/panel interaction
- old valid localStorage consent is automatically migrated once into the canonical cookie
- optional DOM elements are checked before listeners are attached, preventing null.addEventListener runtime errors
- Consent Mode updates when a visitor changes preferences

RECOMMENDED SCRIPT ORDER ON NORMAL PAGES
----------------------------------------
Use the permanent shell first, then the global script:

  <script src="[path-to-js]/pradako-site-shell.js" defer></script>
  <script src="[path-to-js]/scripts.js" defer></script>

The page itself should contain:

  <div id="navbar-container"></div>
  ... page content ...
  <div id="footer-container"></div>

Do not add page-specific fetch("components/navbar.html") or fetch("components/footer.html") code again.
